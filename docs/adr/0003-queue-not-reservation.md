# 0003. 時刻指定の予約ではなく、順番待ちと席割当にする

- **状態**: Accepted
- **日付**: 2026-09-16
- **関連**: 開発プラン 4.5、7.1、7.5

## 背景

「フードコートの席取り問題を解く」には複数の形がありうる。時刻を指定して席を予約する、席を有料の指定席にする、順番待ちに並ぶ、などである。

## 選択肢

| 案 | 内容 | 問題 |
|---|---|---|
| 時刻指定の予約 | 「12:30 から 4 名」で席を確保 | **空席を保証できない。** 前の利用者がいつ立つかは分からない。ノーショーで席が遊ぶ |
| 有料の指定席 | 課金して席を確保し、入替制にする | 無料席の課題を解かない。係員の確認が要る。既存事例（大阪・関西万博、アウトレットの実証）はこの形 |
| **順番待ち＋割当** | 「今から並ぶ」。空いた席を人数に合わせて割り当てる | 待ち時間が読みにくい。呼び出しに気づかない人が出る |

## 決定

**順番待ちと席割当にする。** 利用者向けの呼称は「席の順番待ち」とし、「予約」という語を使わない。

## 理由

- 時刻指定の予約は、退席時刻を制御できない以上、守れない約束になる。守れない約束をする機能は作らない。
- 無料の席という前提を守りたい。課金は導入のハードルを上げ、施設側の運用も重くする。
- 既存製品（VACAN、Airウェイト、EPARK 等）は「混雑の可視化」か「順番待ちのみ」であり、**待ち行列と席割当を結び付けた製品は調査した範囲で見つからなかった**。ここが差別化の軸になる。

## 結果

- 利用者に見える文言から「予約」を排除する。施設向けの掲示でも「順番待ちの方専用席」とする。
- 待ち時間の推定（開発プラン 7.13）が利用者の意思決定に直結するため、幅を持たせて表示し、精度を継続的に測る必要がある。
- 有料の指定席と時刻指定の予約は、非目標（開発プラン 4.6）として明示的にやらない。
