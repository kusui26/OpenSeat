# 0002. ライセンスを Apache-2.0 とする

- **状態**: Accepted
- **日付**: 2026-09-16
- **関連**: 開発プラン 13.1、TRADEMARK.md

## 背景

商業施設とその委託先に導入してもらうことが目的のプロジェクトである。企業の法務が確認しやすいことと、将来ホスティングで収益を得る可能性の両方を考える必要がある。

## 選択肢

| 案 | 利点 | 欠点 |
|---|---|---|
| MIT | 最短・採用障壁が最小 | 特許・商標の条項がない |
| **Apache-2.0** | 明示の特許許諾（第 3 条）と商標の不許諾（第 6 条）があり、企業法務が確認しやすい | SaaS としての「ただ乗り」を防げない |
| AGPL-3.0 | ネットワーク越しの提供でもソース開示義務が生じ、ただ乗りを抑止できる | 社内利用を全面禁止する企業もあり、導入の障壁になる |

## 決定

**Apache-2.0 を採用する。** 名称とロゴは `TRADEMARK.md` で別途管理する。

## 理由

- 本プロジェクトの目的は収益の保護ではなく導入の拡大にある。企業が採用しやすいことを最優先する。
- 特許許諾と商標不許諾が明文化されていることで、企業の法務レビューが短くなる。
- ただ乗りへの対策は、ライセンスではなく商標ガイドラインで行う。Plausible が商標ポリシーで同様の整理をしている。

## 結果

- 第三者が OpenSeat を使って有償のホスティングを提供することを、ライセンスでは禁止できない。名称の使用のみ `TRADEMARK.md` で制限する。
- 貢献者には DCO（`git commit -s`）の署名を求める。CLA は個人開発の段階では重いので求めない。
- SBOM（CycloneDX）を CI で生成する。企業の調達で求められることがあるため。
