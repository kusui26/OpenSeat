# 0016. 画面は API と同じ入口から配り、CSP と置き場の期限を道ごとに分ける

- **状態**: Accepted
- **日付**: 2026-09-22
- **関連**: 開発プラン 9.2・9.13、[ADR-0005](0005-single-container-sqlite.md)、[Phase 2 のプラン](../260921_plan_Phase2.md) PR 6

## 背景

[ADR-0005](0005-single-container-sqlite.md) で「成果物は 1 つのコンテナと SQLite」と決めた。**画面も同じコンテナから配る**ということである（9.2）。

> `apps/server` が API・WebSocket・スケジューラ・**静的配信**を受け持つ。

決まっているのは方針だけで、**同じ入口に 2 種類のものを載せると何が起きるか**は決めていなかった。実際に載せてみると、道が 4 種類ある。

| 道 | 誰のものか | 取りこぼしたら |
|---|---|---|
| `/api/...` | サーバ | **契約どおりの断り**（JSON）が返るべき |
| `/healthz` | 監視 | —— |
| `/assets/...` | 画面の資材 | **404 が返るべき** |
| それ以外 | 画面の中の道（SPA） | **1 枚目が返るべき** |

**同じ `Accept: text/html` の要求が、道によって別のものを返さなければならない。** これを取り違えると、どれも静かに壊れる。

## 選択肢

### 配る場所

| 案 | 利点 | 欠点 |
|---|---|---|
| A. 画面を別のホスティング（Vercel 等）に置く | 配信が速い。組み立てが分かれる | **施設が Docker を 2 つ面倒みることになる。** ADR-0005 の前提が崩れる。CORS と時計合わせが要る |
| **B. 同じコンテナから配る** | **引き渡しが 1 つで済む。** 同一オリジンなので CORS が要らず、時差も同じ返しの中で測れる（9.10） | サーバが静的配信の面倒をみる |

### CSP をどう張るか

| 案 | 利点 | 欠点 |
|---|---|---|
| C. 全体に 1 つ（画面に合わせて緩める） | 簡単 | **API の返しにまで `script-src 'self'` が付く。** 万一 API から HTML が返っても動いてしまう |
| D. 全体に 1 つ（API に合わせて厳しく） | 安全 | **画面が動かない** |
| **E. 道ごとに分ける** | API は `default-src 'none'` のまま、画面は自分の資材だけ | 2 つ書くことになる |

### 取りこぼしをどう扱うか

| 案 | 利点 | 欠点 |
|---|---|---|
| F. すべて 1 枚目に落とす | 実装が 1 行 | **消えた `/assets/index-<古い指紋>.js` に HTML が返る。** ブラウザは JavaScript として読もうとして「予期しない `<`」で止まる。**原因の見当がつかない壊れ方**をする |
| **G. `Accept` を見て、画面を求めた要求だけ落とす** | 資材の取りこぼしは 404 になる | 求め方に頼っている |

## 決定

**B・E・G を採る。** 加えて、置いてよい期間を 2 段に分ける。

| ファイル | 期限 | なぜ |
|---|---|---|
| `/assets/...`（指紋つき） | `public, max-age=31536000, immutable` | **中身が変われば名前が変わる。** いくら置いてもよい |
| `index.html`、`sw.js`、`manifest.webmanifest`、アイコン | `no-cache` | **名前が固定。** 使う前に必ず確かめさせる |

1 枚目には中身から作った札（ETag）を付ける。**配り直すまで札は変わらない**ので、確かめに来ても 304 で終わる。

載せる順序は `/healthz` → 画面 → API とし、**この順序をテストで固定した**（`apps/server/src/app.ts`、`src/web.test.ts`）。

## 理由

- **`/healthz` が先でなければならない。** 画面はどの道も 1 枚目に落とすので、あとに置くと**ブラウザから `/healthz` を開いたときに画面が返る。** 監視の目が塞がれていることに、誰も気づけない。
- **画面と API は互いに触れない。** 画面のミドルウェアは `/api/` から始まる道を素通りさせ、API のミドルウェアは `/api/*` にだけ付く。**どちらを書き換えても、もう一方の守りが変わらない。**
- **取りこぼしに期限を付けない。** 消えた資材の 404 を 1 年間覚え込ませると、**戻したときに直らない。** 期限は「見つかった返し」にだけ後ろから付ける。
- **古い画面を配り続けないことが、実証実験でいちばん効く**（12.5）。現場で直したものが端末に届かないのは、機能が足りないことより困る。だから Service Worker は `autoUpdate` にし、名前が固定のものは毎回確かめさせる。

## 影響

- `WEB_DIR` で置き場を指す。**無ければ配らない** —— 手元でサーバだけを動かすとき、画面は Vite が配る（`/api` だけがサーバへ回る）
- `Dockerfile` が `apps/web` も組み立て、`/app/web` に入れる。**イメージは 1 つのまま**
- 画面の CSP が開けているのは自分の資材と `data:` だけである。**外部の配信網も解析も 1 つも許していない**（CLAUDE.md 7 章の「外部送信」）。解析を入れるときは自前ホストにし、ここを開ける判断を別に記録すること
- `infra/smoke.sh` が、コンテナから画面が配られること・API が画面に飲まれないこと・`/healthz` が塞がれないこと・消えた資材に 404 が返ることを確かめる
- **見直すきっかけ**: 施設が別ドメインで画面を出したいと言ったとき（`connect-src` と CORS の判断が要る）。あるいは資材が増えて、配信網を挟みたくなったとき（ADR-0005 の再検討になる）
