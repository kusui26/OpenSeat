# 0006. 運用費は試行段階のみ開発者が持ち、継続段階は施設が持つ

- **状態**: Accepted
- **日付**: 2026-09-16
- **関連**: 開発プラン 14 章、ADR-0005

## 背景

「OSS なのだから開発は自分がするが、ランニングコストはユーザー企業が負担するのではないか」という問いから検討した。個人開発者が商用ユーザーの本番運用費を持ち続けることは現実的に不可能である。

## 選択肢と調査

OSS プロジェクト 7 件（Ghost、Plausible、Discourse、Metabase、Supabase、Cal.com、n8n）の資金構造を調べた結果、すべてが「**コードは無料、動かす場所は有料**」の構造だった。非営利財団である Ghost の公式ページがこの型を一文で表している。

> We've built a sustainable business around a free core application, funded by a premium managed-service to run it on.

**7 件すべてで、メンテナが商用ユーザーの本番運用費を無償負担している例はなかった。** GitHub の opensource.guide は資金の使い道として「プロジェクトの運用費、たとえばホスティング費用を賄うこと」を挙げており、自腹が前提とされた記述はない。

## 決定

次の 3 つを原則とする。

1. **試行段階のホスティング費は開発者が持つ。** ただし「負担」ではなく**販売経費**として扱い、**覚書に無償期間の終期を日付で明記する**。月 900 円程度、試行の全期間で 4,000 円程度。
2. **継続段階の運用費は施設が持つ。** 施設が直接クラウドに払うか、運用する事業者に払うか、開発者に払うかの違いだけで、開発者が持ち出しになる形は採らない。
3. **どの形になっても成果物は同じ 1 つのコンテナ。** これが ADR-0005 の理由である。

継続段階では 3 つの座組みを施設に示し、**提案の時点で 3 つとも見せる**。無償の終わりを後出しにしない。

| 座組み | 運用主体 | 開発者の負担 | 施設側の摩擦 |
|---|---|---|---|
| **A. 事業者引き取り**（第一目標） | 施設に出入りしている IT 事業者 | ゼロ。請求も契約も不要 | 最小。既存の取引先に 1 項目を足すだけ |
| B. マネージド提供 | 開発者 | インフラ費（回収可）と請求事務 | 小。ただし個人を新規取引先として登録する手間 |
| C. 施設の自前運用 | 施設または親会社の情報システム部門 | ゼロ。構築支援のみ | 大。公開サーバの設置となり情報セキュリティ審査が発生 |

## 理由

- A を第一目標にするのは、商業施設がサイネージ・Wi-Fi・POS・建物管理で既に事業者と契約しており、既存の取引先に 1 項目を足すほうが、個人を新規ベンダーとして登録するより桁違いに軽いためである。事業者側にも「開発費ゼロで継続収入の一行が増える」という動機がある。
- C が重いのは、OpenSeat が社内システムではなく**公開 Web サービス**だからである。来館者のスマホはキャリア回線から接続するため、社内ネットワークの内側に置いても届かない。公開サーバを自社名義で持つことになり、脆弱性診断・WAF の要否・ログの保存方針といった審査がつく。**実証実験の段階で施設に自前ホストを求めるのは、導入ハードルを下げるどころか上げる行為になる。**

## 結果

- 渉外の目標が 1 つ増える。「施設を紹介してもらう」だけでなく「**施設に出入りしている IT 事業者を紹介してもらう**」を加える。
- 座組み B を採る場合、契約は「SaaS 利用料・運用保守の役務提供」として組む。「ソフトウェアのライセンス料・著作権使用料」とすると源泉徴収（10.21%）の対象になりうる。この判断は開業届やインボイス登録より先に決める必要がある。
- 3 つとも成立しない場合、実証の結果を公開してリポジトリを残し、そこで一区切りとする。すべての実験が継続するわけではなく、それは失敗ではない。
