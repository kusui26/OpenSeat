# 困ったときの手順書

**この文書は、慌てている人が読むためのものです。** 上から順に、迷わず実行できるように書いてあります。説明は後ろに置きました。

> **いちばん大事な原則。**
>
> **システムの復旧より、現場を止めないことが先です**（[CLAUDE.md 8 章](../.claude/CLAUDE.md)）。
> 迷ったら **2 分以内に「自由席に戻します」の掲示を出してください。** 直すのはそのあとで構いません。
> OpenSeat は席に物理的な鍵をかけていないので、**止めても人は座れます。**

## 2. 落ちている

### 2-1. 掲示を出す（**最初にこれ**）

下の[掲示テンプレート](#掲示テンプレート)を、入口と各卓に貼ります。**印刷したものを当日必ず持参してください。**

### 2-2. スタッフに伝える

> 「順番待ちのシステムを止めました。**いまから自由席です。** お客様には『お好きな席へどうぞ』とご案内ください。並んでいた方には、順番にご案内します。」

### 2-3. 待っている人への案内

システムが落ちていれば画面にも出せません。**入口で口頭と掲示で伝えます。** 並んでいた順は、スタッフが覚えている範囲で構いません —— **正確さより、待った人を先にすることのほうが大事です。**

### 2-4. 直す

```bash
# いまの状態を見る
railway logs                      # Railway の場合
docker compose logs --tail=100    # 自前のホストの場合

# 起こし直す
railway redeploy                  # Railway の場合
docker compose restart            # 自前のホストの場合
```

**記録は残ります**（ボリュームに置いてあります）。起こし直しただけで消えることはありません。

### 2-5. 15 分で戻らなければ、その日は中止

**実証実験の中止基準です**（[計画書 12.6](260916_plan_OpenSeat.md)）。掲示を出したまま自由席で終日運用し、記録を残して後日やり直します。

## 3. 画面と現実がずれた

**システムに物理的な強制力はありません**（[CLAUDE.md 2 章の 4](../.claude/CLAUDE.md)）。「空いているはずの席に人がいる」「呼ばれた人が来ない」は**想定内**で、そのための操作が用意されています。

| 起きたこと | 誰が | 何をする |
|---|---|---|
| 呼ばれた席に、別の人が座っていた | 利用者 | 座席 QR から「誰か座っています」 |
| 退席したのに席が空かない | 利用者 | チケット画面から「退席しました」 |
| 押し忘れたまま帰ってしまった | スタッフ | 席を空席に戻す（**PR 12 以降**） |
| 全部おかしい | スタッフ | [全席解放](#5-全席解放)（**PR 12 以降**） |

**1 席ずつ直そうとしないこと。** 3 席以上ずれていたら、全席解放して自由席に戻すほうが速く、現場も混乱しません。

## 4. 動いているが、おかしい

### `tickFailures` が 0 でない

**時間を進める処理が断られています。これは必ず実装の誤りです**（業務上の理由で時刻の進行を拒否することはありません）。

1. 掲示を出す（現場を待たせない）
2. ログから拒否の理由を控える（`tick が拒否されました: ...`）
3. **Issue を立てる。** 当日中に直そうとしないこと

### `tickLagMs` が大きい

正常なら 0〜10 秒を行き来します。60 秒を超えたままなら、刻みが止まっています。起こし直してください（[2-4](#2-4-直す)）。

### 呼び出しが画面に出るのが遅い

配信が切れて、5 秒ごとの取り直しに落ちている可能性があります。**利用者には実害が小さい**ので、その日は放置して構いません。`/healthz` の `connections` が 0 に近ければ、配信が誰にも届いていません。

## 5. 全席解放

**すべての席を管理対象から外し、自由席に戻します。** 待っている人のチケットは取り消され、画面に案内が出ます。

> **⚠️ この操作の入口は、まだありません。**
>
> `RELEASE_ALL` はドメインには実装済みですが、**スタッフ用の API と画面は PR 12（認証）で入ります。**
> それまでは、[2. 落ちている](#2-落ちている) の手順（掲示 → 自由席）で代替してください。
> **実証実験までに必ず用意します。**

## 6. 記録を戻す

**ディスクが飛んだ、記録が壊れた、というとき。**

```bash
# 1. 止める
docker compose down

# 2. 戻す（複製から。時刻を指定すればその時点まで巻き戻せる）
litestream restore -config /etc/litestream.yml /data/openseat.db
litestream restore -config /etc/litestream.yml -timestamp 2027-03-06T12:00:00Z /data/openseat.db

# 3. 起こす
docker compose up -d
```

**コンテナは起動時に自動で戻します。** 記録が無い状態で起こせば、複製から引いてきます（`infra/entrypoint.sh`）。上の手順が要るのは「記録はあるが壊れている」ときだけです。

**戻せることを、事前に必ず確かめてください。**

```bash
./infra/restore-drill.sh 's3://BUCKET/drill?endpoint=...'
```

## やってはいけないこと

- **本番の記録を直接編集しない**（[CLAUDE.md 8 章](../.claude/CLAUDE.md)）。調べるのは読み取りだけ。直すなら操作を通すか、スタッフの操作として監査ログに残る形で
- **運用時間中にデプロイしない。** ボリュームを使っているので、再デプロイには短い停止が入ります
- **実証実験の期間中に設定値を変えない**（[計画書 12.3](260916_plan_OpenSeat.md)）。変えるなら A/B の設計に従うこと
- **1 人で抱えない。** 15 分で戻らなければ中止してよい、と決めてあります
